## Affected Routes & Modules
- `src/lib/infrastructure/contabo.ts` — OAuth2 token manager, compute instance API, Cloud Firewall API, Snapshot API.
- `src/lib/infrastructure/cloud-init.ts` — Cloud-init template generation, UFW rules, PostgreSQL 16 tuning, SSL, Node Exporter.
- `src/lib/infrastructure/provisioner.ts` — Asynchronous state-machine provisioner, health check runner, DNS wiring, encrypted credential persistence.
- `src/app/api/admin/infrastructure/*` — Super admin endpoints for server listing, health check trigger, snapshot creation, and rollback.

## Key Interactions & Codepaths to Verify

### 1. OAuth2 Token Caching (Upstash Redis + In-Memory Fallback)
- **Test File**: `__tests__/lib/infrastructure/contabo.test.ts`
- **Assertion**: When Redis has a valid cached token (`expiresAt > now + 30s`), return token without calling Contabo auth endpoint. When token expires, call OAuth endpoint, update Redis with 25-minute TTL, and return new token.

### 2. Contabo Cloud Firewall Automation
- **Test File**: `__tests__/lib/infrastructure/contabo.test.ts`
- **Assertion**:
  - `createOrGetContaboFirewall(name, allowedIps)` builds compliant Contabo Firewall schema and creates rules for port 5432 (Postgres restricted to SaCMS server IPs) and port 443 (Caddy media).
  - `attachContaboFirewallToInstance(firewallId, instanceId)` sends `POST /v1/firewalls/{firewallId}/instances/{instanceId}`.

### 3. Snapshot Lifecycle & 1-Click Disaster Recovery
- **Test File**: `__tests__/lib/infrastructure/contabo.test.ts`
- **Assertion**:
  - `createContaboSnapshot(instanceId, description)` triggers `POST /v1/compute/instances/{id}/snapshots`.
  - `rollbackContaboSnapshot(instanceId, snapshotId)` triggers `POST /v1/compute/instances/{id}/snapshots/{snapshotId}/rollback`.

### 4. Asynchronous State-Machine Provisioning Flow
- **Test File**: `__tests__/lib/infrastructure/provisioner.test.ts`
- **Assertion**:
  - Initial call creates server record with `status: 'provisioning'`.
  - Background polling worker checks `checkServerHealth(serverId)`.
  - Once PostgreSQL responds to `SELECT 1;`, status is updated to `status: 'active'` and `tenant.databaseUrl` is activated.
  - If provisioning times out (>5 minutes), server is marked `status: 'error'` with clear failure reason and resources cleaned up.

## Critical Edge Cases
1. **Contabo API 429 Rate Limit**: Exponential backoff with jitter on Contabo API client.
2. **Invalid / Expired OAuth Credentials**: Graceful error throwing with descriptive message in server logs instead of unhandled promise crash.
3. **Premature DB Queries**: `getTenantDb(tenantId)` rejects queries with `TenantDatabaseNotReadyError` while server is in `provisioning` state.
