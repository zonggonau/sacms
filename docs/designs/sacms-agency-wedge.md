## 1. Problem Statement
Software houses, web agencies, and full-stack freelancers waste 2–3 weeks per client project building custom backend infrastructure, CRUD logic, auth systems, content models, and admin dashboards from scratch. Existing solutions like Strapi or self-hosted CMSs require separate hosting, manual multi-tenant management, and lack modern native AI & MCP (Model Context Protocol) capabilities.

## 2. Demand Evidence
- **Status:** Pre-launch (Hypothesis-to-Validation stage).
- **Core Observation:** Software house dev teams repeatedly spend 20–30% of project budgets on repetitive backend scaffolding instead of client-facing business logic.
- **Validation Goal:** Secure 3–5 web agency tech leads as active pilot users who utilize SaCMS to deliver client portals.

## 3. Status Quo
- **Current Workaround:** Building custom backends from scratch with custom database migrations, or spinning up separate VPS/Strapi instances per client.
- **Cost of Status Quo:** 2–3 weeks of developer time per project ($1,500–$3,000 in dev payroll costs per client) plus ongoing maintenance friction.

## 4. Target User & Narrowest Wedge
- **Target User:** Lead Developer / Tech Lead at Web Agencies & Software Houses.
- **What gets them promoted:** Delivering client web apps in half the time with zero backend maintenance bugs.
- **Narrowest Wedge:** **"Instant Client Backend & AI Engine"** — Spin up an isolated multi-tenant client workspace with custom schemas generated via AI Builder, complete with instant REST/GraphQL APIs, MCP support, and client admin access in 5 minutes.

## 5. Constraints
- Strict multi-tenant data isolation (`tenantId` enforcement on all queries and storage paths).
- High-performance caching and edge rate-limiting (Upstash Redis).
- Localized Indonesian payment gateway (Midtrans) + Enterprise offline license verification.

## 6. Premises
1. **Premise 1 (Problem Reality):** Agencies suffer real pain and lost margin building repetitive backends.
2. **Premise 2 (Sharp Wedge):** Positioning SaCMS as an *Agency Multi-tenant & AI Engine* is 10x more compelling than a generic "Strapi alternative".
3. **Premise 3 (Action Reality):** Codebase features are already comprehensive; the primary bottleneck is active user validation and feedback from real agency pilots.

## 7. Approaches Considered
- **Approach A (Recommended — Agency Accelerator Wedge):** Focus on agency workflows: Multi-tenant client management, instant AI schema generator, Sandpack frontend preview, developer hub (SDK, GraphQL, MCP), and flexible billing.
- **Approach B (Generic Strapi Alternative SaaS):** Direct competition with Strapi Cloud / Contentful for general developers. *(Rejected: High acquisition cost, saturated category, lacks defensible wedge).*
- **Approach C (Enterprise Whitelabel Only):** Target large corporate enterprise licenses only. *(Deferred: Long sales cycles require existing social proof and case studies).*

## 8. Recommended Approach
**Approach A (Agency Accelerator Wedge):** Leverage the existing rich feature set (Next.js 16 App Router, AI Builder, MCP integration, multi-tenancy, and Cloudflare R2 media) to position SaCMS as the ultimate agency backend toolkit.

## 9. Success Criteria
- 3 agency tech leads successfully deploy a live client website backend using SaCMS within 30 days.
- Zero data leakage between isolated tenant environments.
- Time to spin up a production-ready client backend reduced from 2 weeks to under 15 minutes.

### Production Failure Scenarios Accounted For
1. **Dedicated Database Downtime:** `getTenantDb` catches connection errors and falls back to Master DB with error logging instead of uncaught process crash.
2. **Expired API Tokens:** Public API checks `expiresAt < new Date()` and rejects before Redis cache or DB load.
3. **Cache Invalidation Desync:** On every content update/publish in `content.ts`, pattern invalidation (`public_api:tenant:contentType:*`) runs immediately.
